### backend/app/agents/agent_devis.py (lu en entier, 1539 lignes, 83 Ko)
- Cerveau devis : Claude (Sonnet, escalade Opus via supervisor) structure la demande (texte + photos) en postes ; le prix est posé par un moteur de pricing en code (4 étages : prix appris artisan, mémoire, référentiel...), jamais par l'IA ; TVA 0/5,5/10/20 ; taux inconnu -> 20 % ; 5,5 % rétrogradé en 10 % sans RGE valide (F128) ; montants en centimes entiers ; aucune écriture DB dans l'agent.
- Techniques/pièges racontés, transposables à une autre IA :
  - Cache de prompt Anthropic par préfixe : blocs système ordonnés du plus stable au plus variable ; `cache_control: {"type":"ephemeral"}` sur le DERNIER bloc stable ; mémoire artisan et devis en cours APRÈS le point de cache (sinon cache invalidé à chaque tour) ; gain mesuré −10,3 % de coût sur une conversation de démo (0,10374 $ -> 0,09305 $ pour 3 messages) ; les tokens cache_read/cache_creation sont journalisés.
  - Un LLM est non déterministe : deux générations du même devis donnaient des compositions différentes (pose du carrelage sans fourniture, 1 336,50 € TTC d'écart, test du 30/07/2026) -> règle posée en CODE (contrôle de cohérence), pas seulement dans le prompt ; "une consigne de prompt n'est pas un garde-fou".
  - Réponse tronquée (max_tokens) : message d'erreur honnête, pas de relance (elle paierait deux fois pour le même échec) ; `refuser_si_tronquee` dans base_agent partagé avec tous les agents (AUDIT-244) ; "un devis silencieusement incomplet est pire qu'une erreur honnête".
  - Chaîne de modèles épuisée -> `result.is_maintenance` -> message "cerveau en maintenance", sans relancer (AUDIT-205) ; le chat disait avant "tu t'es mal exprimé" alors qu'aucun modèle n'avait répondu.
  - Le modèle répond parfois en prose au lieu de JSON (3 fois sur 3 sur un message court, mesuré le 10/08/2026) -> une relance avec consigne de format ; en dernier recours un poste "à chiffrer" plutôt qu'un 502 ; le rappel de format est le DERNIER bloc du prompt (la position compte).
  - Streaming d'un aperçu (intitulé, désignations) pendant la génération : mesuré 38,6 s pour la réponse complète mais intitulé lisible dès 2,9 s ; JAMAIS de prix en aperçu (les prix du modèle ne sont pas ceux du moteur) ; 86,6 % du temps = génération.
  - Chiffrage des postes en parallèle (`asyncio.gather` borné) : 13,578 s -> parallèle ; 64 % du temps attendait Mem0 (361,8 ms/poste) ; le pooler de connexions avait déjà saturé (AUDIT-166).
  - Mémoire IA (Mem0) : le modèle recopiait des prix de son propre contexte mémoire ; étiquette de source de prix 'artisan' seulement si le montant figure dans les mots de l'artisan ; filtrage de la mémoire par métier (un devis de carrelage recevait des prix d'électricité, D.150).
  - Signaux calculés puis JETÉS à la sérialisation (hypothèses AUDIT-121, alerte AUDIT-152 : un devis signé à 3,7 % du référentiel sans que rien ne le dise ; 592 lignes de devis via le chat sans description AUDIT-176) : leçon = vérifier que ce que le backend calcule arrive à l'écran ; contrat JSON versionné (`schema_version`), ajouts ascendant-compatibles.
  - Borne en code des "2 tours de questions max" (le prompt ne suffit pas : le 27/07 l'assistant a posé 3 salves).
  - Audit AI Act best-effort : un échec d'audit ne bloque jamais le produit ; `model_used='deterministic'` quand c'est du code et pas un LLM.
- Pas de secret en clair. Aucun lien avec Google/stats/photos de site. Réutilisable pour Sitô : si Sitô utilise Claude (textes du site, réponses aux avis), reprendre : prompt caching, détection de troncature et de maintenance, JSON strict avec relance, montants/chiffres jamais produits par l'IA, journal de décision.
