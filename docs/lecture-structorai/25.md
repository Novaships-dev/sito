### backend/scripts/smoke_b2_e2e.py
- Smoke E2E in-process (httpx.ASGITransport sur l'app FastAPI) + vrais services (vrai Claude Vision, vraie base Supabase via asyncpg). Parcours : /health → signup → signin GoTrue → POST client → POST chantier → UPDATE SQL du CA → POST photo (Vision classe avant/pendant/apres/probleme/reference) → scan ticket OCR → vérif DB avant/après /validate.
- Outils/variables : settings.SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_DB_URL ; libs httpx, asyncpg, Pillow (images de test synthétiques dessinées en PIL). Lancement : `PYTHONPATH=backend python backend/scripts/smoke_b2_e2e.py`.
- Contient un secret en clair : mot de passe d'un compte de test (smoke) dans le code.
- Principe : garantie « AI Act » testée par comptage SQL : après le scan, ticket=DRAFT et 0 dépense ; la dépense (source='ticket') n'apparaît qu'après /validate par l'humain, et la marge chantier est recalculée.
- Le compte de test n'est PAS purgé automatiquement (purge manuelle après vérif) ; baseline vérifiée « org vierge ».
- Réutilisable Sitô : modèle de smoke E2E (signup → JWT GoTrue password-grant → API → contrôle SQL) ; le JWT porte app_metadata.organization_id ; photo chantier avec classification avant/après par IA (Sitô a besoin avant/après) ; test d'upload d'image synthétique PIL.
