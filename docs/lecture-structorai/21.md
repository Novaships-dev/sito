### backend/app/services/catalogue_service.py
- Catalogue de postes chiffrables par métier (data/prix/<metier>.json) montré à l'agent Devis : l'agent CHOISIT une référence, le prix est un lookup déterministe (plus d'embedding/seuil). 11 métiers, ~2 043 postes chiffrables sur 2 387.
- Outils: structlog, lru_cache, hashlib sha256. Pas de service tiers. Pas d'env var.
- Leçons: recherche par similarité plafonnait à 37 % (score 0.5862 pour libellé exact; 21/29 scores dans [0.65;0.70[ => non déterministe). Référence positionnelle (ELE-189) a cassé : 224/390 refs (57 %) ont changé de poste, ELE-189 passé de 115 € à 11 500 € (AUDIT-261) => référence = empreinte sha256 de l'id du poste (6 hex), ancien format refusé. Piège: reconnaître l'ancien format par "isdigit" était faux (140 postes dont l'empreinte est tout-chiffres). Détection de métier: set non ordonné => ordre dépend du hash du process (4 résultats différents sur 5 graines) => liste ordonnée; apostrophe "l'électricité" mal découpée. Matières (l, kg) et outillage (168 postes) exclus du menu LLM (l'artisan revendrait son matériel); 5 locations conservées. Doublons désignation+unité => prix médian (écart jusqu'à x3,75 sur "nettoyage fin de chantier"). Les prix ne sont JAMAIS montrés au LLM (rail "zéro invention de prix"). Méthode: mesurer avant d'agir, cliquets/tests de non-régression par audit (AUDIT-NNN, D.NNN).
- Réutilisable Sitô: peu direct (pas de devis). Idées: IDs stables par empreinte, jamais par position; le LLM choisit dans une liste fermée, ne produit pas de chiffres; déterminisme (pas de set); menu court (tokens).
