### docs/MIGRATIONS.md
- Source de vérité des migrations SQL Supabase de StructorAI (001-043 base, puis 044-093, puis migrations horodatées du chat/devis/démo). PostgreSQL 15+, Supabase Frankfurt EU en en-tête (mais le texte dit aussi « Supabase eu-west-1 » pour les migrations appliquées : incohérence dans le doc).
- Outils/commandes : Supabase CLI (`supabase start/stop/status`, `migration new`, `db reset`, `db push`, `db pull`, `db diff`, `link --project-ref`, `migration list`) ; pgvector (ivfflat, 100 lists) ; pg_dump/psql ; CI GitHub Actions job `migrations` (staging sur merge staging, prod sur merge main). Variables : SUPABASE_ACCESS_TOKEN, SUPABASE_DB_URL (+ STAGING_REF/PROD_REF, ACCOUNTING_ENCRYPTION_KEY, ANTHROPIC_API_KEY mentionnées).
- Conventions : jamais modifier une migration appliquée en prod ; idempotence (IF NOT EXISTS) ; BEGIN/COMMIT ; RLS sur toutes les tables ; organization_id + country_code ; index sur toutes les FK ; created_at/updated_at + trigger set_updated_at ; soft delete (deleted_at) ; UUID v4 ; montants en CENTIMES (BIGINT) ; fichier `_down.sql` pour chaque migration ; `NOTIFY pgrst, 'reload schema'` après chaque ALTER (leçon préventive #6) ; numérotation jamais réutilisée ; pas de LOCK TABLE, CREATE INDEX CONCURRENTLY pour gros volumes ; déploiement destructif en 3 étapes (ajout, copie, suppression).
- RLS : deux patterns coexistent : (a) `organization_id = (auth.jwt() ->> 'org_id')::uuid` (anciennes migrations) ; (b) helper `org_id()` avec policies `TO authenticated` (migrations récentes, 4 policies select/insert/update/delete). Audit log ai_decisions immuable (UPDATE/DELETE USING FALSE, INSERT WITH CHECK TRUE). Table sans policy = invisible via PostgREST, seul le backend (pool asyncpg / service_role) y accède (demo_llm_spend). Écritures service_role bypassent la RLS → WHERE org applicatif OBLIGATOIRE en code. Policy `TO anon` pour lecture publique (testimonials publiés). Rôle admin via `auth.jwt() ->> 'role' = 'admin'`. Tables publiques sans org : knowledge_chunks, tva_rules, quests, badges, capsules_index...
- Pièges/leçons :
  * 30/06 et 03/07/2026 : registre Supabase (`supabase_migrations.schema_migrations`) désynchronisé des fichiers (10 puis 11 migrations manquantes, 5 fichiers perdus car appliqués via MCP, 23 lignes seed_* de test dans le registre). Cause : migrations appliquées par DDL direct/MCP hors registre. Réconciliation par INSERT (version,name) sans rejouer le DDL. Règle (CLAUDE.md §5) : toute migration appliquée « via le registre » + vérif `supabase migration list` Local==Remote collée dans un DIAG.
  * CAVEAT DURABLE : ne JAMAIS `supabase db push` sur la prod : le CLI compare par VERSION (schéma de versions mixte NNN_ vs timestamp) et rejouerait les fichiers numérotés. Méthode standard = MCP/psql + inscription registre. (Pour Sitô : partir dès le départ sur des versions horodatées uniquement.)
  * DEUX DESTINATIONS (chantier 7c) : migration à appliquer en prod ET sur la pile Supabase locale des E2E (apply-local.sh) ; oubliée en local → test E2E 18-parcours-complet tombé sur UndefinedColumnError ; garde-fou `verifier_migrations.py` (AUDIT-178). apply-local.sh rejoue tout depuis 000_helpers, inutilisable sur base déjà montée → insertion manuelle au registre (équivalent `supabase migration repair --status applied`).
  * Version enregistrée par le MCP ≠ nom de fichier d'origine → renommer fichiers up/down pour concorder avec le registre.
  * Numéro de facture attribué à l'ÉMISSION (pas à la création) : l'ancien compteur comptait TOUTES les factures de l'année (cause réelle des trous) ; ajout pg_advisory_xact_lock par (org, série) ; trigger interdisant le soft-delete d'une facture émise (correction par avoir).
  * Trigger BEFORE DELETE sur factures : conservation légale 10 ans (fin = 31/12 de année émission+10), prouvé par test rollback réel.
  * Colonnes « calculées puis jetées » (AUDIT-154/234) : valeurs affichées sur la carte du chat sans colonne → perdues à la réouverture ; ajout de colonnes NULLABLE sans DEFAULT (jamais `false`/`[]` par défaut : « rien à dire » = NULL).
  * Mem0 (SaaS tiers, quota 1000/mois) épuisé le 27/07/2026 → 429 → mémorisation silencieusement perdue ; prix appris migrés vers table maison `prix_perso` (Décision 124). Leçon : ne pas confier des données cœur à un SaaS à quota.

  * Backups : Supabase Free/Starter 7 j ; Pro + PITR 7 j (+25 $/mois) ; Team PITR 28 j ; « Pro dès 50 clients » ; pg_dump hebdo manuel vers bucket Storage (30 j) ; restore dashboard 30 min à 2 h.

### docs/OFFLINE.md
- Spec du mode hors-ligne (18/04/2026) avec en-tête de réconciliation du 19/08/2026 : la spec (SQLite+SQLCipher, sync_queue, POST /v1/sync/batch, LWW, multi-appareils) N'A JAMAIS ÉTÉ CONSTRUITE (mesuré : absente de mobile/package.json, pas de route /v1/sync, pas de table sync_queue). Pendant 4 mois la spec a été lue comme un état.
- Ce qui existe vraiment (Décisions 93-96, 23/06/2026, « Option A ») : le serveur fait foi, react-query porte tout : `PersistQueryClientProvider` + cache AsyncStorage (gcTime/maxAge 24 h + buster), `onlineManager` branché sur NetInfo, bandeau `OfflineBanner`, purge du cache à la déconnexion, mutations hors-ligne via `setMutationDefaults` + `networkMode: "offlineFirst"` (mutation mise en PAUSE, pas en échec) puis `resumePausedMutations()` au retour du réseau (survit à la fermeture de l'app). Fichier mobile/lib/offlineMutations.ts. Seulement 4 écritures rejouables (clock-in, clock-out, task-status, create-client), toutes pures-DB ; tout ce qui touche à l'argent et à l'IA reste en ligne par décision.
- Outils cités dans la spec : @react-native-community/netinfo (utiliser isConnected && isInternetReachable), expo-sqlite, expo-secure-store, expo-crypto, expo-camera, expo-audio, FileSystem, idb (IndexedDB pour PWA iOS), Detox pour E2E avion.
- Leçons : (1) une spec datée lue comme un état = fausse promesse marketing (« offline complet » retiré) ; (2) numéros de devis/facture doivent être générés côté serveur uniquement ; (3) PWA iOS : pas de background sync, push web limité (iOS 16.4+), stockage ~50 MB avant prompt, purge possible par iOS ; app native recommandée pour offline lourd ; (4) pas d'envoi client/Stripe/Yousign hors ligne.
- Chiffres terrain (déclarés dans la spec, non mesurés) : ~30 % du temps chantier sans bon réseau, ~10 % des devis créés sans réseau.
- Réutilisable Sitô : le patron simple react-query persisté + mutations en pause (pour réponse à un avis ou ajout de photo en mauvais réseau) ; photo offline : compression ~500 KB JPEG, stockage local puis upload différé vers Supabase Storage, nettoyage > 30 j ; le piège « ne pas construire une couche de sync lourde » ; PWA iOS limitée (important car Fabrice est sur iPhone : pas de background sync).

- Doc mensongère détectée par audit (AUDIT-062 : « promesse doc non tenue ») : le doc décrivait des étages jamais codés ; correction par bandeaux « ÉTAT RÉEL ». Leçon : marquer clairement CODÉ / NON CODÉ.
