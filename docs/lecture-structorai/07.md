### OPS/AUDIT/Z1-AGENTS.md
- Audit lecture seule (21/07/2026) des 19 fichiers `backend/app/agents/` (5 527 lignes) : un Supervisor route chaque intention vers un agent ; 7 findings (AUDIT-001 à 007).
- Méthode : pour chaque capacité, 3 questions « fait-elle ce qu'elle prétend ? est-elle appelée ? un test la traverse-t-il ? » ; on lit le CODE, pas les docstrings.
- Leçons/pannes : (1) escalade Opus jamais déclenchée en prod car `payload={}` toujours passé, et les tests injectaient un payload que le vrai appelant n'envoie pas (tests qui masquent le trou) ; (2) nom d'agent « vision_ia » attendu vs « vision » réel, test validait le nom fantôme ; (3) intention « facture » enqueuée vers un handler inexistant -> tâche qui échoue ; (4) attributs `escalation_model` morts ; (5) chemin chat d'un agent sensible (élec) contourne les garde-fous en code (scrub des verdicts + disclaimer) ; (6) registrations d'agents inertes + docstring trompeuse ; (7) agent de génération de site (`generate_site`) ne journalise pas dans `ai_decisions` (AI Act).
- Patterns bons : agents « zéro invention » (AIError si sortie mal formée), disclaimers non-omissibles injectés EN CODE (pas seulement dans le prompt), `ai_decisions` trace chaque décision IA, résilience (recall mémoire dégrade en contexte vide), fallback en chaîne (relance durcie -> poste « à chiffrer » -> erreur), tâche IA « pending_validation » (l'humain valide).
- Réutilisable Sitô : agent de rédaction de réponse aux avis (`agent_reputation.draft_response` / `draft_review_request`, templates `reputation/templates.json` 3 catégories x 2 tons x 11 métiers + guardrails) ; agent `site_web.generate_pages` (5 pages typées, zéro invention) = proche de la génération de site ; règle « brouillon IA, jamais envoi auto, validation humaine » ; journaliser toute décision IA ; mettre garde-fous en code, pas dans le prompt ; tester avec le VRAI appelant, pas un payload injecté.
